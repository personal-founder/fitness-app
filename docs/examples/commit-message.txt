fix(auth): replace duplicate login code and clear stale sessions

Summary
- Route login through the existing authentication provider and clear all
  local session state when signing out. A signed-out user can no longer
  return to a cached account screen with the Back button.

Problem and rationale
- Login and logout maintained separate copies of session-handling logic.
  The logout path removed the access token but left the cached account
  object and refresh timer active. Navigation could display stale account
  details, and a pending refresh could restore local session state.
- Reuse the existing provider's session lifecycle so credential storage,
  refresh cancellation, and state notifications have one owner.

Changes
- Added a small login adapter around the existing provider.
- Changed logout to cancel refresh work, clear credential/account caches,
  and reset navigation before completing. Repeated logout remains safe.
- Removed the legacy login implementation and duplicated logout branches.
- Reused the provider's validation and error mapping; no new auth library.
- Added regression coverage for stale navigation, pending refresh, repeated
  logout, and a failed remote revocation request. Local sign-out completes
  even when the remote request fails; the failure remains observable.

Decisions and ADRs
- Accepted ADR 0003, docs/adr/0003-centralize-session-ownership.md.
- Keep session ownership in the existing provider. A second state store
  would duplicate lifecycle rules and require synchronization.
- Complete local logout even if remote revocation fails. This prevents a
  network outage from keeping private account details visible. Immediate
  server-side revocation still depends on reaching the service.

Compatibility, security, and operations

Not included and remaining risks
- Signing out every device remains outside this local-session fix. That
  feature requires a separate server-side session-management design.
- During a network outage, remote tokens remain subject to existing server
  expiry/revocation rules. Local caches and refresh work are still cleared.
